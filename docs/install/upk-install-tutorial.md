# ID Plan · 绿联 NAS 安装教程（UPK 应用包版）

> 适用：**绿联 NAS（DX4600 系列等）+ UGOS Pro 系统**。这是最省事的方式——直接用 `.upk` 应用包安装，无需手动配 Docker。
> 你需要：一台绿联 NAS + 一个浏览器。数据集中存在 NAS 上，**工作室多人自动共享**。

> ✅ **推荐**：如果你用 docker compose 方式，请看 [nas-deploy-tutorial.md](nas-deploy-tutorial.md)；本教程用 `.upk` 应用包，装完是个完整的「应用」，在应用中心能看到图标。

---

## 一、这是什么

`.upk` 是绿联 UGOS Pro 的应用安装包，**一个包内含前端 + 后端两个容器**，安装后自动装配好。你在应用中心能看到一个「ID Plan」应用图标，点开就在浏览器新标签页访问 `http://<NAS-IP>:28080`。

---

## 二、前置准备

- ✅ 绿联 NAS 已开机、能上网（浏览器能打开 NAS 管理页）。
- ✅ 电脑和 NAS 在同一个网络（或能远程访问）。

> **哪个版本？** 绝大多数 Intel 系绿联 NAS（DX4600 等）用 **amd64** 版；只有 Apple Silicon / 部分 ARM 机型才用 arm64。拿不准就选 amd64。

---

## 三、安装步骤

### 第 1 步：下载 .upk 包

到 GitHub Releases 页下载 `amd64_com.chengcheng.idplan_0.7.0.0001.upk`：
👉 [https://github.com/chengcheng067/idplan/releases](https://github.com/chengcheng067/idplan/releases)

下载后放在一个好找的地方（比如桌面）。

### 第 2 步：上传开发者授权文件（仅首次需要）

> 这个授权文件是绿联开发者资格认证（`ugdev.sig`），**如果之前装过 ID Plan 已经传过，可跳过此步。**

1. 把绿联发给你的授权文件重命名为 `ugdev.sig`（注意后缀，别变成 `ugdev.sig.txt`）。
2. 打开 UGOS Pro 的**文件管理器**，进入**管理员账号的个人文件夹**。
3. 把 `ugdev.sig` 放在**个人文件夹根目录**（位置参考 `/volume1/homes/<管理员用户名>/ugdev.sig`）。

### 第 3 步：开启应用开发授权（固件 ≥ 1.16 才需要）

1. 打开 **应用中心** → 右上角 **设置** → **应用开发设置**。
2. 点 **授权**，完成整机开发者授权。
3. 找不到「应用开发设置」说明固件低于 1.16，跳过即可。

### 第 4 步：手动安装

1. **应用中心** → 右上角菜单 → **手动安装**。
2. 选择第 1 步下载的 `.upk` 文件。
3. 若弹出「应用配置」表单：
   - **数据源**：填 `remote`（团队共享数据库，推荐）
   - **后端 API 地址**：填 `/api`（保持默认，nginx 会自动转发，**不用**改成带前缀的地址）
4. 等待安装完成（约 2-3 分钟，包体 186MB）。

> 💡 没弹配置表单也没关系——装完后在「应用中心 → ID Plan → 应用配置」里可随时改。

## 五、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面白屏 / 资源 404 | 访问了带前缀的地址 | 确认浏览器访问的是 `http://<NAS-IP>:28080/` **根路径**，不要加 `/idplan/` |
| 应用装不上 | 授权或固件问题 | 确认第 2/3 步授权完成；看应用中心报错 |
| 装上了但打不开 | 容器没起来 | Docker 套件 → 容器列表，看 `idplan` 和 `idplan-backend` 是否都「运行中」 |
| 数据不共享 | 数据源没设对 | 应用配置里把「数据源」改成 `remote` |
| 想升级 | — | 重新打包后（构建号 +1），再走一次「手动安装」覆盖即可，**数据不丢** |

## 五·补、arm64 机型说明（UGREEN ARM 架构 NAS）

当前只发布 **amd64** 安装包（发布方无 arm64 真机，不做无验证发布）。
arm64 机型用户两条路：

1. **等**：arm64 UPK 排在后续批次（CI 镜像产线 `upk-images.yml` 早已支持
   `linux/arm64` 双构建，缺的只是手动触发与打包——路线已定，见
   `docs/release-checklist.md` 第 6 节）。
2. **现在用**：走 **Docker compose 形态**（[教程](nas-deploy-tutorial.md)）。
   ghcr.io/chengcheng067/idplan 是**多架构镜像**（linux/amd64 + linux/arm64
   同一 tag），`docker pull` 会按你机器的架构自动选层——arm64 NAS 直接可用。

## 六、数据在哪里 / 怎么备份

- 数据存在 Docker 的 **`idplan-data` 卷**（NAS 的 docker 目录下）里的 `changxia.db`。
- 备份：Docker 套件 → 存储空间 → 找到该卷，把 `changxia.db` 拷走即可。
- 覆盖安装只重建容器，**不动数据卷**，所以升级安全。

### 应用内「保存备份 / 从备份恢复」（需要配一次令牌）

应用内的备份按钮走服务端的 `/api/backup` 通道。它是 **fail-closed** 的：服务端没配
`IDPLAN_AGENT_TOKEN` 就一律拒绝（备份是明文全量数据，不能裸奔）——没配时点保存会
提示「备份通道需要鉴权」。配一次，两侧同值即通：

1. **服务端**：UGOS → Docker 套件 → 找到 `idplan-backend` 容器 → 编辑 →
   **环境变量**新增一行 `IDPLAN_AGENT_TOKEN`，值填**你自己想的一串随机字符**
   （比如 `idplan-` 加 16 位随机字母数字）→ 保存并重启容器。
2. **应用内**：ID Plan → 设置 → **NAS 服务** → 把**同一串值**粘进去 → 保存
   （页面提示已保存即生效，不用刷新）。
3. 之后顶栏「保存备份」/「加载备份」即可正常使用；导出文件同时可存到 NAS 共享
   文件夹之外的地方（应用内备份 ≠ 卷级备份，两者互补：卷级拷的是运行中的库文件，
   应用内导出的是经过一致性快照的完整备份包）。

> 历史说明：0.8.2 及以前的 UPK，compose 模板没有这个环境位、前端令牌也是构建期
> 烤死的——应用内备份结构性不可用。0.8.2.0002 起模板已带该环境位（见上文第 1 步），
> 前端也改为设置内可配。
