# ID Plan · 绿联 NAS 部署教程（开发小白版）

> 你只需要一台**绿联 NAS**（UGOS Pro 系统）+ 一个浏览器，**不需要**电脑上装任何 Docker 或编程工具。
> 本教程从零开始，每一步都点哪个按钮都写清楚了。

> 📌 **镜像版本怎么定**：Docker 镜像由 [docker-build.yml](../../.github/workflows/docker-build.yml) **手动触发**构建，镜像标签就是触发时填写的版本号（形如 `idplan:0.8.0`）。所以下面的版本号请替换成 Releases 里 **最新的 `docker-<版本>` 标签**，本文示例统一写作 `<版本>`。若你手上有 `.tar` 离线包，直接导入即可，不必拉取镜像。

---

## 一、先明白三件事（1 分钟读完）

1. **ID Plan 是什么**：项目排程工具，覆盖 9 个主板块 / 29 套阶段套餐（室内 / 景观 / 建筑 / 软件 / 市场 / 影视 / 婚礼 / 咨询 / 旅游）。部署到 NAS 后，你和工作室的伙伴用它来管理项目阶段、任务、成员，数据集中存在 NAS 上，**多人自动共享**，不用再手动导 JSON。
2. **为什么要在 NAS 上跑**：因为团队的库要放在一个所有人能访问的地方。NAS 就是这台"家里的服务器"。
3. **你需要装几个"东西"**：其实就一个"应用",它由 2 个小容器组成（前端负责页面、后端负责存数据），我用一个"项目"文件帮你一次性把它们装配好，你不用手动一个个建。

---

## 二、前置准备

- ✅ 你的绿联 NAS 已经开机、能上网（浏览器能打开 NAS 管理页）。
- ✅ 电脑和 NAS 在同一个网络（或能远程访问 NAS 管理页）。

> **如果 NAS 上还没装 Docker：**
> 打开桌面「**应用中心**」，搜索 **Docker**，点「安装」。装好后它会自动在 NAS 上创建 `docker` 共享文件夹。

---

## 三、开始部署（两种方式，任选其一）

### 方式 A：从 GitHub 云仓库拉镜像（推荐，以后升级方便）

这一步用的是**镜像仓库**（ghcr.io），NAS 会自动从云端下载，不用你手动传文件。

1. 打开桌面「**Docker**」应用。
2. 点左侧「**项目**」→ 右上角「**创建**」。
3. 给项目起个名字，比如 **idplan**。
4. 把下方 `idplan-nas-compose.yml` **文件内容整段复制**，粘贴进「Compose 文件」的编辑框里（或直接上传这个文件）。
5. 点「**立即部署 / 确定**」。项目初始化后会自动开始拉镜像（可能要几分钟，视网速）。
6. 部署完成后，点「**容器**」应该能看到 **idplan** 和 **idplan-backend** 两个容器都在运行。

### 方式 B：离线导入 .tar（不想依赖网络时）

如果你已经下载了 `.tar` 镜像文件（见文末"如何拿镜像"），用这种方式：

1. 先把 `.tar` 文件传到 NAS 上。可以放进共享文件夹（如 `docker` 文件夹）。
2. 打开桌面「**Docker**」→ 左侧「**镜像**」→「**本地镜像**」。
3. 点「**导入 / 手动添加**」，选择你上传的 `.tar` 文件，导入。
4. 导入一个前端镜像 + 一个后端镜像（共 2 个 .tar）。
5. 然后回到「**项目**」→「**创建**」，同样粘贴 `idplan-nas-compose.yml`，但把 `image:` 那两行改成你导入的镜像名（见下），再点部署。

> 方式 B 的 compose 里 `image:` 要改成你本地导入的镜像名，例如：
> ```yaml
> idplan:
>   image: idplan:amd64        # 你导入的前端镜像名
> backend:
>   image: idplan-backend:amd64  # 你导入的后端镜像名
> ```

## 四、选择数据源（关键：决定团队能不能共享）

部署完成后，在「**容器**」或「**项目**」里找到 **idplan** 容器，点「**编辑**」→「**环境变量**」，设置：

| 变量 | 值 | 作用 |
|---|---|---|
| `VITE_DATA_SOURCE` | `remote` | **团队共享模式**（数据存 NAS 后端，所有人看到同一份） |
| `VITE_API_BASE_URL` | `/api` | 保持这个值不要改，nginx 会自动转发 |

> 如果只想自己一个人用、数据存浏览器本地（离线），把 `VITE_DATA_SOURCE` 改成 `local` 即可，`VITE_API_BASE_URL` 留空或 `/api` 都行。

---

## 五、打开与验证

1. 在浏览器输入：`http://<NAS的IP>:28080`
   - 例如 NAS 的 IP 是 `192.168.1.100`，就打开 `http://192.168.1.100:28080`
2. 如果能正常打开 ID Plan 页面，说明成功。
3. **验证团队共享**：在页面上建一个项目（或导入演示备份）→ 把 `backend` 容器重启一下 → 再刷新页面，数据应该还在。

## 六、常见问题（小白避坑）

| 问题 | 原因 | 解决 |
|---|---|---|
| **拉镜像很慢 / 失败** | 国内访问 ghcr.io 慢 | `Docker → 镜像 → 设置` 里配置镜像加速器（如 `https://docker.m.daocloud.io`），保存后重试。 |
| **页面打不开** | 端口被占用或容器没起 | 检查端口 `28080` 是否被占用；确认两个容器都在运行。 |
| **`/api` 报错 / 反代失败** | 前端连不上后端 | 确认 `VITE_API_BASE_URL=/api`，且 `backend` 容器在运行；`links` 配置别删。 |
| **重启后数据没了** | 数据卷没配对 | 确认 compose 里有 `volumes: - idplan-data:/data`（这份 compose 已含，别删）。 |
| **担心数据在不可见位置** | 具名卷默认在 docker 目录 | 可改 compose 为 `- /volume1/docker/idplan-data:/data` 存到你可见的共享文件夹。 |

## 七、如何拿到镜像（两种来源）

1. **GitHub Releases（最快，离线导入用）**：去仓库 Releases 页，找**标签形如 `docker-<版本>` 的最新一条**，下载里面的 `.tar` 文件（按你的 NAS 架构选 amd64 或 arm64）：
   - https://github.com/chengcheng067/idplan/releases
   - 前端：`idplan-amd64.tar` / `idplan-arm64.tar`
   - 后端：`idplan-backend-amd64.tar` / `idplan-backend-arm64.tar`
2. **ghcr 拉取（在线，升级方便）**：NAS 直接拉（`<版本>` 换成上一步查到的标签）
   - `ghcr.io/chengcheng067/idplan:<版本>`（前端）
   - `ghcr.io/chengcheng067/idplan-backend:<版本>`（后端）

> 镜像是**手动触发**构建的，不是每次提交都自动发版。如果某个标签拉不到，说明该版本尚未构建镜像，请换用 Releases 里确实存在的 `docker-<版本>` 标签，或改用 `.tar` 离线导入。

> 怎么知道 NAS 是 amd64 还是 arm64？`控制面板 → 关于本机` 里能看到机型/架构描述；拿不准就下 amd64（绝大多数系列）。

## 附：本教程配套文件

| 文件名 | 作用 |
|---|---|
| `idplan-nas-compose.yml` | 一键部署的 compose 文件（粘贴/上传用） |
| `idplan-nas-compose-amd64.yml` | 离线导入版（.tar 为 amd64） |
| `idplan-nas-compose-arm64.yml` | 离线导入版（.tar 为 arm64） |

**升级方法**：改 compose 里的镜像版本号（如从 `0.8.0` 改成更新的版本），再重新「部署」一次即可，数据不丢。版本号必须对应一个已发布的 `docker-<版本>` 镜像。
