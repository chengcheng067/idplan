## 背景

- 你的库是 Dexie（IndexedDB）库名 `changxia`，v0.5 及以前为 version 1；
  v0.6 首次启动会触发 `version(2)` 迁移（新增 4 个索引 + 老 `externalId`
  键清理），并弹出**不可跳过的备份对话框**——导出成功才允许打开库。
- 迁移三级可回滚：L0 迁移函数抛异常 → Dexie 事务自动回滚保持 v1；
  L1 迁移前备份在应用内整体替换恢复；L2 删库回旧版。
- **新旧版本可共存回退**：v0.5 安装包（或旧构建）仍能读 v1 库；一旦 v0.6
  打开过库（version 已升 2），v0.5 将以 version 1 打开失败——这是 Dexie 的
  行为，L2 是唯一完整回滚路径，所以 P2 的基线备份必须做。

## P1 · 演练前置（5 min）

- [ ] 下载并暂存 **v0.5 现行版**安装包（用于 L2 回滚），放到一个能找到的目录
- [ ] 下载 **v0.6 新构建**
- [ ] 确认要演练的机器上能正常打开 v0.5 且项目数据完整
- [ ] 准备一个目录存放演练产物（备份包 / 截图 / 报告），下称 `DRILL_DIR`

## P2 · 迁移前基线快照（10 min）★ 最重要的护身符

- [ ] 打开 v0.5 → 顶栏「保存备份」→ 导出 `changxia-baseline-v0.5.json` → 存 `DRILL_DIR`
- [ ] **核验备份包**：文件大小 > 0；用文本编辑器打开，确认 `"schemaVersion"`、
      项目 / 任务条数与你的真实数据一致（记录：项目数 ___、任务总数 ___、成员数 ___）
- [ ] 再在应用内随便开一个项目，确认应用内数据与备份包条数一致
- [ ] （可选双保险）浏览器 / Electron 的 IndexedDB 目录复制一份原始库文件
      （Electron：`%APPDATA%/changxia/IndexedDB/` 整目录），存 `DRILL_DIR`

## P3 · 升级与闸门观察（5 min）

- [ ] 安装 / 启动 v0.6
- [ ] **预期**：出现不可跳过的「迁移前备份」对话框（不是可关闭的普通提示）
- [ ] 按对话框引导导出迁移前备份 `changxia-pre-migration.json` → 存 `DRILL_DIR`
- [ ] 与 P2 基线包对比：两者条数应一致（迁移前导出的就是 v1 原始数据）
- [ ] 导出成功后对话框放行 → 应用进入主界面

## P4 · 数据完整性核对（15 min）

逐项勾选，任何一项不符立即停下（跳 P7 回滚）：

- [ ] **项目数一致**：首页项目列表条数 = P2 记录值；无重复、无缺项
- [ ] **任务全量**：抽 2 个项目逐条核对任务标题 / 批次 / 负责人 / 截止日
- [ ] **任务完成态**：原来已勾选完成的任务，在 Agent Board 里 status 显示
      `done`（v0.6 由 `done` 反推）；未完成任务显示 `draft`（不是 `ready`，
      这是设计口径——防灌满 Ready 队列）
- [ ] **成员完整**：成员数一致；设过密码的成员登录仍正常
- [ ] **时间轴不塌**：每个项目的 Timeline 批次条数、起止日期与 v0.5 一致
- [ ] **指派不丢**：「我的任务」里各成员的任务条数与 v0.5 一致
- [ ] 开发者工具（如可用）抽查：任一任务对象含新字段 `status / source /
      externalId / artifacts` 等且不报错

## P5 · v0.6 新功能冒烟（10 min）

- [ ] 顶栏出现「Agent Board」入口，页面可开
- [ ] 设置 →「Agent 与本地库」区块显示席位与库占用
- [ ] 成员页新建一个 Agent 类型成员（agentKind 随意填），席位计数 +1；
      列表默认不显示它，开「显示 Agent」后可见
- [ ] Agent Board「Apply payload」粘贴一份 3 条任务（1 条依赖另 1 条）的
      payload → 预览无 rejected → commit → 看板出现 2 条新任务、批次为
      最后一个可见批次
- [ ] Ready 队列出现被依赖阻塞前的可执行任务；给一条任务点 claim 成功
- [ ] 生成 handoff bundle 并复制，肉眼确认不含任何成员密码 / 联系方式

## P6 · 二次演练 / 导入导出闭环（5 min）

- [ ] v0.6「保存备份」导出 v3 备份包 → 再用「加载备份」导回 → 数据条数不变
      （验证 v3 roundtrip 在真实数据上成立）
- [ ] 同一份 payload 再导入一次 → 任务数不变（幂等，不产生重复）

- [ ] 启动 v0.5 → 空库 → 「加载备份」选 **P2 基线包** → 核对数据完整
