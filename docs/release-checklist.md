### 1.1 ✱ 冻结窗口执行序列（2026-10-14 定 —— 跑「全量总信号」时照此执行）

> 为什么单列：这**不是**「跑一次 `npx vitest run`」。本轮实测出**四类会让总信号失真的条件**，来源各不相同、形态完全一样 —— **全量红、单跑绿**：① 进程级全局泄漏（`matchMedia`，稳定假红）；② 另一个全局的间歇泄漏（`__APP_ENV__`）；③ 产物残留（`built-assets` 自检 loud-fail）；④ **机器争用**（见下）。

0. **前置**：稳定红清零；守卫判据收敛完成。
1. **宣布冻结**：全队停手 = **冻 `src` 编辑 + ✱ 冻跑批并发**
   - 冻编辑：见上一节（`staleInputs()` 是全局判据）。
   - ✱ **冻并发（2026-10-14 新加）**：**同时跑多份全量会让读数失真**。现象：真机用例里 20s 的元素等待会**随机**超时、**哪条先超时每次都不同** ⇒ 表现为「同一个输入、两次跑出来的红集合不同」（实测：一轮 25 条、另一轮 7 条，组成还不同）。
   - ✱ **「常态 66s」这个基线已于 2026-10-14 作废，别再引用。** 原文写「常态 66s 的跑批变成 9m29s / 14m51s（≈10 倍）」，但：① 全仓 `grep` 只有那一处 —— **没有第二处出处、也没有口径**（哪条命令 / 哪些文件集 / 多少用例）；② 本轮实测同规模读数是 **44 文件 / 329 用例 / wall 568.84s 与 565.94s** ⇒ 两个数**根本不是一个量级**，那句「≈10 倍」极可能是**跨口径比较**（正落进已知两族错误之一：**量取到了别人身上**）。**直接后果**：读数器按它判「>1.5× ⇒ 疑似争用污染」，把一轮 **0 失败 0 跳过**的干净读数标成「不可信」—— 这是**假警报**。假警报的代价是双向的：不只让阈值形同虚设，还会**掩盖真缺陷**（人一旦发现报警没用，就会把检查关掉）。
   - ✱ **改法（新规则）**：争用阈值只能用**同规模可比读数**；**首次同规模读数定义基线**（连口径一起记：命令 + 文件数 + 用例数 + HEAD + wall + tests 时长），**从第二次同规模读数起阈值才生效**；**没有同规模基线时不出判定**，只打印「基线未定义（本轮即基线）」。
   - ✱ **别只靠「停手」这句话**：实测过一次通信失效 —— 负责跑批的线在等长跑批时用了**阻塞式等待**，指挥的「停」「开跑」等四条消息**全部积压到两轮跑完才被它看到**。⇒ 结论：**冻结不能建立在「它会收到我的话」上**，必须落在**脚本自检**上（见第 5 步的起跑自检）。
2. **状态核对**：工作树干净 **且 `git diff --cached` 为空**
   - ✱ 理由：**`git diff --cached` 才是事实**。「我以为我留在了未暂存状态」可能是错的 —— 本轮实测过一次「已 staged 但被提交锁挡住」的改动，被另一人的 `git commit` 一并带走（那人 `add` 的是窄路径，**问题在 `commit` 侧没带 pathspec**）。⇒ 提交一律 `git commit -- <明确 pathspec>`。
   - ✱ **可执行判据（2026-10-14 加；别用眼睛扫 `git status`）**：
     ```bash
     [ -z "$(git status --short)" ] || { echo "工作树不干净 ⇒ 不许开窗"; git status --short; exit 1; }
     ```
   - ✱ **为什么这条非加不可 —— 当轮真实事故（未遂）**：宣布冻结后，一条线自报「空闲」却又接着做了一轮**变异实验**，**变异留在工作树上**（18 行未提交）。而完整真机族里**恰好含那个被变异的 spec** ⇒ 若没拦住，两轮都会红，读数里会出现一条**假稳定红**，它**长得和真稳定红完全一样**，会直接把「非确定性」的判定引向错误分支。
     ⇒ 推论（比事故本身重要）：**「全队停手」不等于「工作树干净」**。变异实验自己会造出一个不干净的树，而做变异的人**不觉得**那算「在飞改动」。
   - ✱ **状态判据 ≠ 内容判据**：`git status` 干净只说明「相对 index 没变」，**不代表等于你要测的那一代**。⇒ 再记一条内容判据：跑前 `git rev-parse HEAD` + 对族内关键 spec 做 `git hash-object`，**两轮必须逐字相同**（只比 HEAD 不够：HEAD 相同而工作树被改，hash 会不同）。
   - ✱ **内容判据的写法（2026-10-14 补，来自实测）**：用 `git diff --quiet && git diff --cached --quiet`，或 `git hash-object <file>` 对上 `git rev-parse <rev>:<path>`。**不要用「再查一次它就自愈了」** —— 实测出现过 ` M` 而 `git diff` 为空的 **stat-only** 情形（mtime 变了、内容 = HEAD 未变）；**「复查后消失」与「本来就没改」在证据上不等价**（前者可能只是 git 刷了 stat 缓存，也可能掩盖了真的内容改动）。
   - ✱ **变异实验的归位纪律**：任何变异**还原之前**，这条线不算回到「可跑状态」。还原后要自证，且**第三条必须是内容判据**（`git hash-object` 对上目标提交的 blob），不能只跑 `git status` —— 「状态干净」与「内容一致」是两回事。
     ⇒ 更根本的解法是**机械拦阻**（脚本开始记还原基线、结束无论成败都自动校验，多出改动就**非零退出**），不靠人肉三查 —— 本轮实测：人肉三查**一次就滑出去了**。
   - ✱ **判据的取值域要收到「真正会影响结论的那一部分」（2026-10-14 加）**：收得太宽 ⇒ **过度封锁**；收得太窄 ⇒ 漏。实测两次：
     - **太宽**：某「构建前树必须干净」的守卫用裸 `git diff --quiet`（全树）⇒ 把一笔**未提交的 `docs/` 改动**算成脏而拒绝构建。**那次拦的是真事、但属「不该拦的类别」** —— 因为 `docs/` `qa-scratch/` 改动**不会进产物**。
       ⚠️ **该笔未提交的 `docs/` 改动是指挥者自己留下的**（改完忘提交）—— 参见第 2 步「不得把改动留在未落点态」：**立纪律的人自己犯规一次，代价是挡了别人一次。**
     - **正确宽度**：不同守卫看不同的东西 ——

       | 守卫 | 该看什么 | 为什么 |
       |---|---|---|
       | **构建前**（rebuild-guard） | **构建输入**（`src` `electron` `index.html` `vite.config.*` `tailwind.config.*` `postcss.config.*` `package.json`） | 只有这些会被**烤进产物** |
       | **跑批前后**（browser-run） | 「**产物代前后一致**」= 硬判据；**`tests/` 有未提交改动** = 警告（「本轮被测对象可能混合了别人的在飞测试改动」） | 产物已定 ⇒ `src/` 脏**不影响**本轮读的是哪份产物；但 `tests/` 脏会让**「测的是什么」不明确** ⇒ 该报，不必拦 |

       `docs/` `qa-scratch/` `outputs/` 等 ⇒ **完全不相关，别管**（否则每次都被写文档的人挡住）。
   - ✱ **「守卫本身要过『会报 + 不误报』两条自证」这一条今天抓到两次真缺陷**（缺一不可，只证一条等于没证）：
     ① 某开关放行时仍被裸 `git diff --quiet` 判失败 ⇒ **永远返回 1，形同废纸**；
     ② 上面那条过度封锁 ⇒ **把自己人挡住**。
     ⇒ 结论：**守卫自己也是被测对象。** 写完的判据必须**跑一遍「它该报的时候报了吗 / 它不该报的时候报了吗」**，两条都要有原始读数。
   - ✱ **「逐字一致」类断言的证据串必须能被别人重跑复核（2026-10-14 实测）**：本轮出现过**手抄/复述哈希少两个字符**（38 位，SHA-1 是 40 位）却用它断言「逐字一致」的情形 —— 结论当时其实是对的（另有人用完整 40 位核过），但**那个串本身已无法被任何人复核**，等于一句死证据。⇒ 规则：**哈希/校验串一律从命令输出机械复制**，别手敲、别凭记忆复述；打印时**把两边都打出来**（不要只打「一致 / 不一致」）。
   - ✱ **判「是不是同一份东西」一律用内容，不用时间戳（2026-10-14 加）**：两个**互镜像**的实测 ——
     - 状态变了**不等于**内容变了：`git status` 里的 ` M` 可以是 **stat-only**（mtime 变、blob 与 HEAD 逐字一致）；
     - 时间戳变了**不等于**产物代变了：`build-dist/index.html` 的 mtime 从 `03:44:00` 变成 `03:50:13`，而其内容哈希与 `assets/` 清单**逐字未变** ⇒ **同一代**。
     ⇒ **产物代只报内容两项**（`index.html` 的 blob 哈希 + `assets/` 名字与大小）；**mtime 只能当「什么时候建的」这条附注，不能当身份。**
   - ✱ **两条 git 机制的盲区（同期实测）**：
     ① **`git commit -- <pathspec>` 对未跟踪的新文件不生效** —— 会**静默什么都不提交**。⇒ 新增文件要先 `git add`。「带 pathspec 提交」这条纪律的本意是「只提交我点名的东西」，而在新文件上它是**静默失效**，不是报错。
     ② **提交撞 `cannot lock ref`**（并发写者把 HEAD 移走）⇒ **重试是唯一正解**；**不许用 `--amend` / `reset` 去「绕」**。
3. **清产物目录 → 构建**：`rm -f build-dist/assets/*.css build-dist/assets/*.js && npm run build`
   - ✱ `emptyOutDir:false` 的代价：残留的旧哈希 bundle 会让 `built-assets` 自检**按设计 loud-fail**，一次报出一批**与本次变更无关**的红（实测 94 条全在 `print-a4-visual*` 家族）。
   - ✱ **不要下「禁止重建产物」这类指令（2026-10-14 教训）**：为了让「刚验过的那一代产物」留着而当门 —— 结果任何人一动 `src` 它立刻过期，**浏览器族整组静默 skip**，验证变成假的（实测：解冻后 5 分钟内就过期 3 个输入）。产物本来就要在第 3 步重建，**保它不是目的**。⇒ 正确说法是上一节的「跑批前重跑一次 `npm run build`」，不是「谁都别 build」。
   - ✱ **重建 `build-dist` 也必须串行（2026-10-14 加）**：它是**共享资源**，且 `emptyOutDir:false` ⇒ **两份并发重建会往同一个目录里写两代 bundle**，产出混合代（极端情形下让 `built-assets` 自检按设计 loud-fail，报出一批与本次变更无关的红）。⇒ 同一条「冻并发」纪律**也适用于 build**，不只适用于跑批。
   - ✱ **在共享资源上留副作用的脚本，必须把这件事打印出来**：实测有脚本（变异自证 / 读数器）会**顺带重建 `build-dist`**，而使用者以为那代产物被「冻住」了 ⇒ 事后才发现产物已被换掉。⇒ 解法是**让副作用可见**（脚本开头一行醒目提示 + 头注释），**不是**给它加 `--no-build` 开关（那会让 stale 树的问题回来，代价更大）。
   - ✱ **「清产物 → 构建」这个动作本身是破坏性的（2026-10-14 实测，有确切机理）**：`rm -f build-dist/assets/*.css *.js && npm run build` 是**先删旧 bundle 再写新的** ⇒ 一个**已经在加载中**的页面会去取**旧哈希**的 bundle，而那一刻它**已被删、新的还没写完** ⇒ **404 ⇒ 白屏 ⇒ `waitForSelector('header')` 20s 超时**。
     ⇒ 实测形态：一条线 03:43:19 重建出 `index-Cc8tWzL0.js`，另一条线 03:44:00 又重建出 `index-wpNglQp2.js`，**中间那次真机跑批红了一条、失败点与当事人改动毫无关系**（红在 `openShell` 的 `waitForSelector`）。
     ⇒ 结论：**重建前必须确认没有跑批在跑**；并且**不要靠「大家都收到了我的话说别重建」** —— 实测这种纪律会输给竞态。
4. **一步判据（可执行；别靠「我刚构建过」这个感觉）**：
   ```bash
   n=$(find src electron -type f \( -name '*.ts' -o -name '*.tsx' \) -newer build-dist/index.html | wc -l)
   [ "$n" = "0" ] || { echo "产物过期（$n 个输入比它新）⇒ 先构建再跑浏览器族"; exit 1; }
   ```
   并**记下产物时间戳 + 提交号**。
   - ✱ 为什么要拦在跑批前：**过期会让浏览器族整组 skip，而这一批的意义正是「把真相看清楚」** —— skip 恰好把真相藏掉。此判据与 spec 内的守卫**同源**（共享助手 `CAN_RUN_FRESH` 用的就是它）。
   - ✱ 读数要带产物代：本轮两次「互相矛盾的观测」（两人读数互斥）根因都是**读数没带来源**。
   - ✱ **这个判据只覆盖一半（2026-10-14 实测到的盲点）**：它只盯 `src`/`electron` 的 mtime，**不覆盖「跑批期间有人改 `tests/` 或有人提交」** —— 本轮 HEAD **真的中途变过**，而这条自检**全程绿**。若那次改的是**测试文件**，读数就被污染了而**无人察觉**（改测试不会让产物过期）。⇒ 补：跑前/跑后各记 **`git rev-parse HEAD`** ＋ **`tests/` 下最新 mtime**（＋可选：族内 spec 的 `git hash-object`），**任一变化 ⇒ 该轮标「不可信」**。
   - ✱ **`过期输入 = 0` 是「下界」判据，不是「相等」判据（2026-10-14 修正）**：它只证明「**没有源文件比产物新**」，**不证明「产物 = 当前源码构建出来的」** —— 只要有人在**构建之后**把源码改回去（或 checkout 到旧版本），过期计数照样是 0，而产物是**另一代**。
     ⇒ 所以 **不许把「过期输入 = 0」当作「产物 = HEAD」**。产物真正的身份标识是**产物代**：`build-dist/index.html` 的内容哈希 ＋ `assets/` 清单（名字 + 大小）。这也正是第 5 步为什么要「跑前跑后各记一次产物代」。
     ⇒ 实测触发：一条线 03:43:19 构建出 `index-Cc8tWzL0.js`、另一条线 03:44:00 构建出 `index-wpNglQp2.js`（**bundle 名是内容哈希 ⇒ 两次构建输入的内容不同**），而两次查「过期输入」**都是 0**。
   - ✱ **受控实验结果：构建**逐字**可复现（2026-10-14 实测，`REPRODUCIBLE=1`）**：同一棵树 + 无并发，连续构建两次 ⇒ `index.html` 内容哈希与 `assets/` 清单**逐字一致**。
     ⇒ 于是上面那条可以**升级成存在性证明**：**产物代（bundle 名 / `index.html` 哈希）不同 ⇒ 构建时树里必然存在「非 HEAD 内容」。** ⇒ **针对那一代产物做出的任何读数，都不能用来判 HEAD 的性质。**
     ⇒ 所以「跑前跑后产物代一致」不只是卫生要求，它是**「这轮读数对 HEAD 有效」的必要条件**。
     ⇒ **推论（实测教训）**：**构建前不只要查「有没有并发 build」，还要查「树里有没有未提交的 `src` 内容改动」** —— 否则会把在飞改动**烤进产物**，然后污染所有读到它的人。实测这条是某次假红的直接成因之一（构建者当时只查了并发）。
   - ✱ **「副作用是意外的」与「副作用是必要的」，处置不同（2026-10-14 升级）**：
     - 脚本**顺带**重建产物（意外副作用）⇒ **让它可见**就够（打印一行醒目提示）。
     - 脚本**必须**重建产物（必要副作用，如变异自证：变异得在产物里 spec 才看得见）⇒ **可见不够用，得给它自己的空间（隔离出独立 outDir）**。
     ⇒ 因为「变异构建」与「共享产物」在**结构上不兼容**：它一跑就把共享 `build-dist` 换成「HEAD + 变异」那一代，此时**任何人跑批读到的都是被污染的那一代** —— 实测这已造成一次「与当事人改动毫无关系」的假红。**靠纪律让它别撞是次优解；能隔离的就别靠纪律。**（可行性评估已立项。）
   - ✱ **但隔离有个反直觉的前提：空间给了，还要证明「东西确实在那个空间里」（2026-10-14）**。隔离只解决「互不干扰」，**解决不了「读的到底是哪一份」**。若某条路径**没跟随**新目录，产物会建在新目录、而探针仍读旧目录 ⇒ **变异根本没进它读的那份产物 ⇒ 绿得毫无意义** —— 这是**隔离方案自己造出的一类新假绿**。
     ⇒ 所以**不变量是前置条件，不是配套**：任一隔离方案落地前，必须先有「**变异确实在产物里**」的断言（回读产物、或在服务目录与构建目录之间做同源断言），**读不到即红**。该断言自带「会报 + 不误报」两条自证。
     ⇒ **这条与隔离无关地现在就成立**：今天那套跑批里「探针读到了带变异的那份产物」**从未被验证过，只是碰巧成立**（构建与探针都指向 `build-dist`）⇒ 是在补一个**既存的洞**。
   - ✱ **技术债要按「风险放大器」记，不是按风格记（2026-10-14 盘点）**：本轮实测到「同一逻辑多份复制体」两例 —— 某 helper **9 份副本**；`const DIST_INDEX =` **本地定义在 34 个 spec**、`function startStaticServer` **本地副本 17 个**、`tests/` 里 **41 个文件**提及 `build-dist`。
     ⇒ 危害不是「难看」，是：**任何「路径 / 口径」类改动都有「漏一条」风险，而漏了不报错、只静默用旧值**（⇒ 直接落进「**没报**」那一族）。⇒ 凡要动这类全局口径，先问「**一共几处、我改了几处、剩下几处为什么不用改**」。
5. **全量跑两次（串行）**，并**记录每个文件的耗时**（把「争用」从现象变成可测量量）。
   - ✱ **开跑前先做「起跑自检」（2026-10-14 加）**：起跑那一瞬间若检测到**别的 `vitest` / 读数器进程** ⇒ **立刻退出并报人**，别跑完再说。理由：并发污染只在**那几十秒的窗口**里发生，事后看总时长**未必看得出来**（小幅重叠会被吞掉），只有「起跑瞬间的快照」能钉住它。
   - ✱ **进程表的 `CreationDate` 是「某次跑批何时开始」的唯一客观来源** —— 比任何自报、任何文件 mtime 都硬。本轮 r1 就是靠它判出「起跑时刻早于指挥信号」而作废的（`Get-CimInstance Win32_Process`；`wmic` 在本机不可用）。
   - ✱ **两轮读数必须各自留一份**（如读数器用 `--label=r1` / `--label=r2` 分文件落盘）。**别用「每轮删同一路径」来防混淆** —— 那会把**第一轮的原始输出覆盖掉**，两次就没法并排对账「哪几条飘」。分轮次命名同时解决两件事：「旧读数混进新一轮」与「两轮都要留证」。2026-10-14 实测踩过：固定路径 + 每轮先删 ⇒ 第二次覆盖第一次。
   - ✱ **读数器的汇总也必须落盘**，不能只打到 console。本轮实测：`tail -30` 把汇总块（族规模 / 过期计数 / 进程检测 / 三维 / 争用判定）截走 ＋ 汇总只走 console ⇒ **那一轮的「跑前进程检测」永久缺失、事后无法复核**。⇒ 汇总落盘是硬要求。
   - ✱ **读数必须带「通过 vs 总数」两个量（2026-10-14 加）**：vitest 汇总是 `Tests N passed | M skipped (T)` ⇒ **`total`（括号里的 T）在跳过时并不缩小，缩小的是 `passed`** ⇒ 「**跳过了但数照算**」这件事在 total 上**完全看不出来**（徽章若用 total 就永远不变）。这和我们那条最要紧的已知限制是**同一个坑的两个面**（第一面：跳过的用例不算通过；第二面：一个只看总数的数字看不出被跳过的部分）。⇒ 报告三维时**两个量都要给**，对外数字/徽章统一取 **`passed`** 口径（保守侧），**`skipped` 单独报**。
   - ✱ **产物代也必须「跑前 / 跑后」各记一次，不一致即该轮作废（2026-10-14 加）**：记 `build-dist/index.html` 的内容哈希 + `assets/` 目录清单（名字 + 大小），跑完再记一次。
     - 与第 2 步的「`HEAD` + `tests/` mtime 跑前跑后」**同源**：那条防「**代码代**中途变」，这条防「**产物代**中途变」。**光有前者不够** —— 实测出现过「代码代没变、产物代变了」，并且当场把一条真机跑批污染成一条与当事人改动无关的红。
     - 这条**不能靠「我已通知大家别重建」**：实测那条纪律输给了两条线动作与指令之间的**竞态**。**纪律要么落在机器判据上，要么它不存在。**
   - ✱ **判据的匹配串必须与编码无关（2026-10-14 加）**：实测脚本日志是 **GBK**，用中文串去 grep/poll ⇒ **不报错、只是静默不匹配** ⇒ 被误读成「那行不存在」（实测有人为此空转 90 秒并误判一次）。⇒ **探针一律用 ASCII 哨兵**（如 `[guard]` / `[restore]` / `[clean]`），并在脚本头注释写明编码。
     - 这条与「**反例必须落在判据的观测窗口内**」是**互补的一对**：那条防「反例在窗口外」，这条防「**判据看不见窗口内**」。两者都会让「没报」伪装成「事情没发生」。
   - ✱ **证据/锚点必须落在 append-only 或轮次命名的路径上**。本轮两例：① 某 spec 的截图目录固定 ⇒ 后一次运行**静默覆盖**前一次，先前引用的时间锚点**当场蒸发**（事后核不到）；② 变异日志用 `/tmp/mut1.log` 这类固定名 ⇒ 任何一次重跑都覆盖，「原样输出」只在当时可核。⇒ **固定路径上的产物只能当「当前状态」，不能当「历史证据」**。
   - ✱ **中间产物（勘察清单 / 计划 / 逐条定位）也要有耐久落点，不能只活在一条聊天消息里（2026-10-14 加）**。实测触发：一条线把「22 处逐条定位 + 拆分方案」交在**消息**里就停了（它的判断是对的 —— 不开一个做不完的大件停在中间）；但**消息不是耐久路径**，会话一断那份勘察就没了，下一个会话得重新勘察一遍。
     ⇒ 处置：把它**完整落进任务账**（或代码旁注释），从此「停在勘察完成」真的是一个抗中断的**落点**。
     ⇒ 这与「**落点是抗中断的唯一手段**」是同一条：**判断「在哪停」时，先看那个停止点是不是耐久路径上的。**
   - ✱ **指挥者自己也要守窗口纪律**：本轮 r1 作废三条里有一条是**指挥者中途提交**（一笔纯 `docs/` 提交）把 HEAD 弄变号 ⇒ 两轮「同一 HEAD」的内容判据当场失效。`docs/**` 对跑批结果**零影响**，但**判据一旦破就没法事后补救**。⇒ 窗口开启到末轮结束之间，**谁都不提交**。
   - ✱ **反例必须落在判据的观测窗口之内（2026-10-14 实测）**：给「跑批期间的变动」写反例自证时，**把反例放在了跑批之前** ⇒ 跑前快照已包含它 ⇒ 判据当然报「未变」，**看起来像「判据没生效」，实际是反例根本不在窗口里**。改法：反例要在**判据观测的那段时间内**发生（脚本为此补了与 `--touch-src-during` 对称的 `--touch-tests-during`）。⇒ 通用形态：**「没报」有两种可能 —— 判据坏了 / 反例不在窗口里**，必须先排除后者再下结论。
   - ✱ **量不能太钝（同轮自证逼出来的）**：判「`tests/` 有没有被动过」，只记**最新 mtime** 不够 —— 改一个**较老**的文件不改变最大值 ⇒ 判据**静默失效**。改用 **mtime 总和**（任意文件被动过，总和必变）。这正是已知两族错误里的「**量太钝**」：判据在取值域里只有一种可能结果。

### 1.2 ✱ 隔离树（`git worktree`）使用纪律（2026-10-14 定）

> 用途：把「会污染共享产物的跑批」挪到自己的一棵树里 —— 例如**变异自证**（它**必须**把变异烤进产物，与共享 `build-dist` **结构上不兼容**，见 §1.1 第 3 步）。
> 为什么选它而不是「加环境变量改 outDir」：**worktree 的隔离是结构性的**（spec 按 `__dirname` 读**树内**产物 ⇒ 34 份本地 `DIST_INDEX`、`staleInputs`、`vite.config.ts` 的 `outDir` **全都不用改**）；env 方案是**约定性的**（漏设一个变量就串味 ⇒ 那时才需要「探针确实读到变异目录」的不变量）。**结构性的约束不需要长期纪律来维持，约定性的需要。**

1. **建树**：`git worktree add --detach ../disc-probe-<线名> HEAD`
   - ✱ **绝不能建在别人的目录里**：建前 `test -e`；**唯一命名（带线名）**。
   - ✱ **`node_modules` junction 也算「写入别人的目录」**。实测踩过：有人把 junction 建进了别人的 `../disc-probe`。
2. **接依赖**：`fs.symlinkSync(<主仓>/node_modules, <树>/node_modules, 'junction')`（实测 npm/vite/playwright 全透明；Windows 建 junction 权限实测可建）。
3. **拆树**：`git worktree remove --force <dir>` → **再删残留的 `node_modules` junction** → `git worktree list` 复核只剩主仓。
   - ⚠️⚠️ **删 junction 不许用 `rm -rf`**：它是 Windows 目录**重解析点**，在 Git Bash / MSYS 下 `rm -rf` **可能递归进目标** ⇒ 会把**主仓的 `node_modules` 内容真删掉**（不是只删链接）。
   - ✅ **正确删法**：`cmd //c rmdir "<junction 路径>"`（`rmdir` 对 junction **只移除重解析点**，不递归）。
   - ✅ **删完必须两条自证**：① 目标仍完好（`ls -d <主仓>/node_modules` 有内容）；② 链接已消失。
   - ✱ 现场证据（**两次同型，其中一次不是本会话的**）：`disc-probe-gating`（今天）与 `changxia-verify`（更早）都只剩一个 junction —— 说明 `worktree remove --force` 不清 junction 是**稳定行为**，不是偶发。
4. **worktree 的 gitdir 是绝对路径 ⇒ 位置敏感、用完必须删**。现场证据：`disc-probe` 因**仓库从 C: 盘搬到 E: 盘**（C 盘旧目录已无 `.git`）而**注册悬空** —— 留下一棵 5.1M 的无主树 + 一份一个月前的旧产物。

## 踩坑汇编（两轮实测）

| 坑 | 现象 | 解法 |
|---|---|---|
| `patch_backend_tar` 漏新文件 | 后端层缺新模块 | 脚本按 git tracked 推导；新增 `.ts` 自动入层，`.tsx` 按白名单不入（后端不需要） |
| ugcli `${VAR:-}` | `project validation failed: variables not set` | 裸 `${VAR}` + project.yaml parameters 声明 |
| 同名 asset 重复传 | 真 422「Validation Failed」 | 先 GET assets 实态再决定传不传 |
| curl `--retry` 上传 | 假「Validation Failed」 | 别加 retry；以实态为准 |
| python 改写 CRLF 文件 | LF 混入行被统一成 CRLF，spec 的 `indexOf('\n')` 假红 | 源码级锚点用 `\s*` 正则（换行无关） |
| 注释写 z 数字 | toast spec 正则误抓，层级断言假红 | 注释语义化，数字只出现在类名里 |
| 空库加引导层 | 全浏览器族点击被遮罩拦（timeout 海） | 探针 flag + 身份 helper 尾部加「消卡」步骤，同轮适配 |
